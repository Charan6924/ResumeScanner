GIT BEST PRACTICES & WORKFLOW
==============================

GOLDEN RULES
------------
1. Never commit directly to main
2. Always pull latest main before branching
3. Write clear, descriptive commit messages
4. One feature/fix per branch
5. Keep commits small and focused


BRANCHING WORKFLOW
------------------

1. Start from latest main:

   git checkout main
   git pull origin main

2. Create a new branch:

   git checkout -b feature/your-feature-name

   Branch naming conventions:
   - feature/add-search-endpoint
   - fix/upload-validation-bug
   - refactor/cleanup-duplicate-code


3. Make your changes and commit:

   git add .
   git commit -m "Add search endpoint with vector similarity"

   Commit message tips:
   - Use present tense: "Add feature" not "Added feature"
   - Keep first line under 50 characters
   - Be specific: "Fix PDF upload crash on empty file" not "Fix bug"


4. Push your branch to remote:

   git push -u origin feature/your-feature-name

   The -u flag sets upstream, so future pushes just need: git push


5. Create a pull request:

   Option A - Using GitHub CLI:

   gh pr create --title "Add search endpoint" --body "Description of changes"

   Option B - Using GitHub web:

   Click "Compare & pull request" button
   Fill in title and description
   Click "Create pull request"


USEFUL COMMANDS
---------------

Check current status:
   git status

See what branch you're on:
   git branch

See commit history:
   git log --oneline -10

Discard uncommitted changes to a file:
   git checkout -- filename

Undo last commit (keep changes):
   git reset --soft HEAD~1

Stash changes temporarily:
   git stash
   git stash pop


THINGS TO AVOID
---------------
- git push --force (destroys history)
- Committing .env or secrets
- Vague commit messages like "fix" or "update"
